# Requirements: SIP Endpoint Management

> Internal service logic for SIP endpoint initialization and configuration.

## Overview

This document specifies the requirements for the SIP endpoint management module in flutter_nmsip. The endpoint is the foundation layer that initializes platform channels and enables all SIP operations.

## Business Context

**Problem**: Flutter applications need to communicate with native Android SIP (PJSIP) library while supporting background processing and real-time event updates.

**Solution**: Service-based architecture using Android Intents with callback registration and event broadcasting.

## Stakeholders

- **Developers**: Need clean API for SIP operations
- **Application**: Requires background call handling
- **End Users**: Expect reliable call functionality

## Functional Requirements

### FR-1: Endpoint Initialization

The system SHALL initialize the SIP endpoint via platform channels:
- Create MethodChannel "flutter_sip2" for commands
- Create EventChannel "flutter_sip2_events" for real-time events
- Register BroadcastReceiver for service responses
- Return initialization state with existing accounts/calls

**Acceptance Criteria**:
- [ ] Platform channels registered successfully
- [ ] Event stream lazy-initialized
- [ ] BroadcastReceiver listens for service events
- [ ] Returns Endpoint state (accounts, calls, connectivity)

### FR-2: Service Configuration

The system SHALL provide methods to configure SIP service:
- `changeServiceConfiguration(Map<String, dynamic>)`: User agent, STUN servers
- `changeNetworkConfiguration(Map<String, dynamic>)`: Network settings
- `changeCodecSettings(Map<String, dynamic>)`: Audio/video codec preferences
- `updateStunServers(int accountId, List<String>)`: Per-account STUN servers

**Acceptance Criteria**:
- [ ] Configuration passed to PjSipService via Intent
- [ ] Callback ID tracked for async response
- [ ] Success/error returned to Flutter layer
- [ ] PlatformException wrapped as FlutterSip2Exception

### FR-3: Event Broadcasting

The system SHALL broadcast real-time SIP events:
- `registration_changed`: Account registration status updated
- `call_received`: Incoming call notification
- `call_changed`: Call state changed (answered, held, etc.)
- `call_terminated`: Call ended
- `message_received`: SIP message received
- `connectivity_changed`: Network connectivity changed

**Acceptance Criteria**:
- [ ] Events emitted via EventChannel
- [ ] Event data serialized as JSON
- [ ] Multiple subscribers supported
- [ ] Event stream survives app backgrounding

### FR-4: Exception Handling

The system SHALL handle errors uniformly:
- Catch PlatformException from method channels
- Wrap in FlutterSip2Exception with code and message
- Preserve original error information
- Provide clear error messages to developers

**Acceptance Criteria**:
- [ ] All platform calls wrapped in try-catch
- [ ] Exception code preserved (e.g., "SIP_ERROR")
- [ ] Message includes error details
- [ ] Stack trace available for debugging

## Non-Functional Requirements

### NFR-1: Performance

- Endpoint initialization < 500ms
- Event broadcast latency < 100ms
- No blocking operations on main thread

### NFR-2: Reliability

- Callback ID sequential generation prevents race conditions
- BroadcastReceiver cleanup on engine detach
- Event sink null-checking prevents crashes

### NFR-3: Background Support

- Service-based architecture enables background execution
- Events broadcast even when app is backgrounded
- Intent routing decouples Flutter from PjSipService

## Dependencies

- **Android**: PjSipService (native SIP library)
- **Flutter**: MethodChannel, EventChannel, BroadcastReceiver
- **Data**: JSON serialization via ArgumentUtils

## Out of Scope

- Account creation/registration (see sdd-account)
- Call operations (see sdd-call)
- Native PJSIP implementation details
